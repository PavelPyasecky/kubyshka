# Задание на разработку

Документ для исполнителя, который продолжает работу над «Кубышкой». Требования — в [`REQUIREMENTS.md`](REQUIREMENTS.md), устройство — в [`ARCHITECTURE.md`](ARCHITECTURE.md), интерфейс — в [`UX.md`](UX.md), запуск — в [`DEPLOY.md`](DEPLOY.md). Макеты экранов — в `prototype/` (открывается в браузере) и `prototype/shots/`.

## Что уже работает

| Слой | Состояние |
| --- | --- |
| Сервер | Fastify на `apps/api`. Создание семьи, приглашение кодом, возврат доступа, `POST /api/sync` с разрешением конфликтов по `updated_at`. Миграции накатываются при старте |
| Клиент | React на `apps/web`. Локальная база Dexie как источник истины, фоновая синхронизация с очередью, PIN-блокировка, установка на домашний экран |
| Экраны | Главная, ввод операции, список операций, накопления, аналитика, лимиты, «Ещё», первый запуск, стартовые остатки |
| Домен | `packages/shared`: деньги в копейках, периоды, баланс счетов, расчёт накоплений, подсказка категорий, правила рекомендаций, шифрование семьи. 26 тестов |
| Записи | Содержимое синхронизируемых записей шифруется на устройстве. Сервер хранит конверт и шифротекст. Ключ восстановления показывается при создании семьи |
| Инфраструктура | `docker-compose.yml` с Postgres, Caddy и ночными дампами. `scripts/smoke.mjs` проверяет сервер целиком |

## Правила

1. **Деньги — целое число копеек.** Вычисления с плавающей точкой запрещены везде, включая промежуточные значения.
2. **Новая доменная логика живёт в `packages/shared` и покрывается тестом.** В компонентах остаётся только отображение.
3. **Источник истины — локальная база.** Компоненты не ходят в сеть. Запись идёт через `persist` из `apps/web/src/db/repo.ts`, которая сама ставит запись в очередь синхронизации.
4. **Контракт синхронизации менять только целиком:** схема в `packages/shared/src/entities.ts`, миграция в `apps/api/migrations`, проверка в `scripts/smoke.mjs`. Новое поле без миграции молча потеряется.
5. **Бюджет сборки — 250 КБ сжатого JavaScript.** Сейчас 136 КБ основной скрипт и 2 КБ регистрация service worker. Новая зависимость допустима, только если она дешевле своей задачи. QR приглашения — пакет `uqr`.
6. **Тексты интерфейса — по-русски, обычными предложениями.** Без восклицательных знаков, без капса, без «Ой!». Ошибка объясняет, что делать дальше.
7. **Минимальная высота нажимаемого элемента — 44 точки.**
8. **Код самодокументируемый.** Комментарий уместен там, где объясняет ограничение, а не пересказывает строку.

Перед сдачей каждой задачи:

```bash
npx tsc --noEmit -p packages/shared && npx tsc --noEmit -p apps/api && npx tsc --noEmit -p apps/web
npm test --workspace @kubyshka/shared
npm run build --workspace @kubyshka/web
node scripts/smoke.mjs http://127.0.0.1:3100   # если трогали сервер
```

## Этап A. Без этого нельзя пользоваться ежедневно

### A1. Карточка операции и редактирование

Сейчас тап по операции вызывает `confirm()` на удаление — так ошибку ввода не исправить.

- Макет: `prototype/shots/d12-detail.png`, разметка в `prototype/index.html`, фигура «Карточка операции».
- Создать `apps/web/src/features/transactions/TransactionSheet.tsx`: модальный лист с суммой, категорией, счётом, датой, автором и заметкой. Кнопки «Изменить» и «Удалить».
- «Изменить» открывает экран ввода с заполненными полями и сохраняет ту же запись (тот же `id`).
- Удаление — мягкое, через `softDelete`, с возможностью отмены в течение пяти секунд.
- Готово, когда: операцию можно открыть из списка и с главной, поправить сумму, категорию, счёт, дату и заметку, изменения доезжают на второе устройство.

### A2. Полный ввод операции

Экран ввода даёт только сумму, категорию и последний счёт. Нужны остальные поля, не удлиняя основной путь.

- Основной путь не меняется: сумма, тап по категории, сохранено. Всё дополнительное — за иконкой рядом с чипом счёта.
- Добавить выбор даты (сегодня, вчера, календарь) и поле заметки.
- Для перевода подставлять копилку как счёт назначения по умолчанию.
- Готово, когда: ввод вчерашней траты с заметкой занимает не больше пяти действий, а обычный расход — по-прежнему два.

### A3. Перевод в копилку с экрана накоплений

Кнопка «Перевести» на экране накоплений открывает пустой ввод.

- Открывать ввод с типом «перевод», суммой, равной разрыву между отложенным и лежащим в копилке, счётом списания — самым полным расчётным, счётом зачисления — копилкой.
- Готово, когда: перевод суммы разрыва делается двумя нажатиями с экрана накоплений.

### A4. Управление счетами

- Экран из «Ещё» → «Счета» → «Править»: создание, переименование, смена иконки и цвета, тип, начальный остаток, архивация.
- Архивный счёт исчезает из выбора при вводе, но остаётся в истории.
- Счёт с операциями удалить нельзя, только архивировать.
- Готово, когда: можно завести второй накопительный счёт и он попадает в копилку на экране накоплений.

### A5. Управление категориями

- Экран из «Ещё» → «Категории»: создание, переименование, иконка, цвет, порядок перетаскиванием, архивация.
- Архивная категория не предлагается в подсказках, но остаётся в отчётах.
- Готово, когда: добавленная категория сразу появляется в подсказках на экране ввода.

## Этап B. Надёжность

### B1. Повтор синхронизации после ошибки

`apps/web/src/sync/engine.ts` при ошибке помечает состояние `offline` и ждёт внешнего события. Если первая синхронизация после установки упала, данные не приедут, пока пользователь не свернёт и не откроет приложение.

- Добавить повтор с нарастающей паузой: 2, 5, 15, 60 секунд, дальше раз в минуту.
- Повторы останавливаются при успехе и при уходе приложения с экрана.
- Готово, когда: при выключенной сети приложение продолжает работать, а после включения синхронизируется само, без действий пользователя.

### B2. Видимое состояние синхронизации

- В «Ещё» показывать «Синхронизировано минуту назад» или «Нет сети, N изменений ждут отправки».
- На главной ничего не показывать, пока всё в порядке.
- Готово, когда: при выключенной сети в «Ещё» видно число неотправленных изменений.

### B3. Обновление приложения

Service worker зарегистрирован в режиме `prompt`, но предложения перезагрузиться нет.

- Тонкая полоса сверху: «Доступна новая версия» и кнопка «Обновить».
- Готово, когда: после выката на сервер открытое приложение предлагает обновиться и обновляется по нажатию.

### B4. Face ID

- Подключить WebAuthn поверх существующей PIN-блокировки (`apps/web/src/state/lock.ts`). PIN остаётся запасным способом и не удаляется.
- Макет: `prototype/shots/d9-lock.png`.
- Готово, когда: на iPhone приложение открывается по Face ID, а при отказе предлагает PIN.

Для каждого экрана до появления данных: аналитика, накопления, лимиты. Пустой экран предлагает действие, а не сообщает об отсутствии данных.

Покрыть `ledger.ts` (баланс при переводах между счетами), `suggest.ts` (подсказка выбирает недавнюю и частую категорию) и движок синхронизации (локальная правка новее серверной не затирается ответом).

## Решения, которые нельзя принимать самостоятельно

1. **Смысл числа «Отложено».** Решено: главное число — прогноз со знаком «≈», факт уходит в нижнюю строку. Менять только по согласованию.
2. **Что делать с отрицательным месяцем.** Решено: показывать отрицательное число и столбец вниз, не обнулять.
3. **Доступ без почты.** Почту, SMS и внешние входы не добавлять. Сессию можно вернуть со второго устройства или по имени и PIN. Записи без ключа восстановления не читаются, в том числе из консоли сервера: владелец явно заменил прежнее восстановление через консоль на ключ, который показывается при создании семьи и позже в «Ещё».
4. **Мультивалютность, роли, несколько копилок** — сознательно вне области работ.

## Известные ограничения

- Прогноз расходов линейный: делит потраченное на прошедшие дни. На коротком месяце с крупной покупкой в начале он завышен. Это принято осознанно, усложнять без запроса не нужно.
- Конфликт правок решается по последней записи целиком, без слияния по полям.
- Регистрация закрывается после создания первой семьи. Повторно открыть её можно только через базу.
